Flagship · v0.5 · Open Source

Where Is My Money Going? · statements in, a categorised answer out, on your own machine

I couldn't answer that question from my own bank statement. A year of UPI transfers to names that meant nothing to me weeks later, and every app that promised to sort it out wanted my full financial history uploaded to a server first. So the constraint came before the design: nothing leaves the machine. Everything else follows from that. Deterministic Python parses the statements, and a local model (Gemma 4 via Ollama) only ever labels rows that have already been extracted, so a hallucination can never turn into a rupee figure. Two agents then refine the result. One finds the people in the ledger from two-way UPI flow, the other re-checks every tag the first pass was unsure about.

The part I'd actually talk about in an interview is a bug I wrote myself. A failed model call was returning a plausible-looking {"category": "uncategorized", "confidence": 0.0}, and the pipeline stored it as genuine output. So 285 transactions the model had never seen sat in the database labelled as its work, and the dashboard reported "80% uncategorized". The model itself was fine. It's a reasoning model, and asking it for JSON the naive way made its output degenerate mid-string. Turning the thinking channel off and passing a real JSON Schema fixed it outright. The lesson stuck harder than the fix: a fallback that imitates success hides the bug that caused it. Failures now return nothing at all, and the row stays visibly untagged. Once I knew what to look for I found two more of the same species, including a prose quality gate that was rejecting 100% of valid output while a canned fallback went out in its place.

Also in there: instalment-plan detection off the counters printed on card statements, cadence-based recurring-charge detection, duplicate-charge and unmatched-refund checks, cross-statement reconciliation of card bills from both sides, and a typeset Spend Analysis PDF. Statement parsers are selected by sniffing document content, not filenames. Re-ingesting the same file is a no-op via a content hash. 158 backend and 10 frontend tests, with ruff, mypy, ESLint and tsc clean in CI, plus a job that fails the build if a phone number, a real UPI handle or an employer identifier ever reappears in source.
